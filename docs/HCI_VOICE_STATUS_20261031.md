# 2026-10-31 HCI 语音接入

## 原因与证据

本机 IOHID 日志中的遥控器描述符只有 Report ID 1，MaxInputReportSize=9。
同一时段，Apple PacketLogger GUI 已显示目标 IPRC1000 的连续 HID Interrupt Receive F7，
适配器仍为 F7=0、仅收到 ID 1。扩大用户态回调缓冲无法补齐描述符中没有声明的报告。

本次完整保存的抓包位于本机 `/private/tmp/IPRC1000-live-20261031-0938.pklg`，
448415 字节、1209 条记录、无尾部残缺。原件含其他设备流量，不应发布。
新接收解析器对 Apple 工具转换后的真实记录回放得到 639 帧、204480 个 PCM 样本。
这仅验证解析，不等于实时输出验收。

## 本次接入

- 保留 IOHID 按键通道，新增独立 HCI 语音启动/停止按钮。
- 使用已安装的 Apple PacketLogger，验证 `anchor apple` 签名。
- 用户主动启动后通过系统管理员认证创建临时捕获子进程，不安装常驻服务、不改蓝牙调试默认值。
- 先从系统配对信息按产品名找到唯一 IPRC1000；逐帧校验其地址与 HID Interrupt Receive。
  PacketLogger 的实时显示名称不作为身份条件（详见下方真机修复）；
  同时验证 ACL handle、分片标志、ACL/L2CAP 长度、动态 CID、完整 A1 F7 01 及 count=320。
  通道类型由 Apple 解码器分类，不在任意字节中搜索 F7。
- PCM 接入既有连续重采样与 BlackHole 输出。启用 HCI 后不混入 IOHID 音频，避免重复。
- 临时提权进程仅启动固定路径 Apple 工具、转发输出、监督连接；
  主应用停止或退出时关闭双向通信管道，监督进程终止并回收捕获子进程。
- 额外提供用户主动启用的本机中文转写。Speech 请求强制本机识别；模型不可用时报告错误，不退回云端。
  转写文本显示在连接诊断页，不自动合成 Fn 或覆盖用户按键映射。

## 真机拒收原因及修复（20261031.3）

首次认证后临时抓取进程确实运行，但初版接收器仍收到 0 帧。
新增协议头元数据诊断后，同一次用户语音产生至少 300 个 F7 候选，
`addressMatch=true`、`nameMatch=false`、`rawWords=661`，类型为 HID Interrupt Receive。
实时 PacketLogger 的显示名称与离线文件不同，初版强制名称完全等于 IPRC1000，误拒收了真实目标。
20261031.3 去掉该显示名称条件，保留系统唯一配对身份、逐帧地址及协议结构检查。
自测加入地址显示别名用例，真实抓包的名称别名变体仍正确解析 639 帧。
更新后用户完成认证并按住遥控器麦克风说测试句。应用实际收到 264 帧，
按 320 样本/帧、16 kHz 推算为 5.28 秒；Speech 完成结果为
“今天测试遥控器语音输入12345”。该结果来自应用实际界面，不是离线重放。
本次没有从 Mac 自带麦克风取音，转写输入直接来自通过身份和协议检查的 F7 PCM。
UI 的 HCI 帧数每 50 帧发布一次，因此显示 250；VoiceController 的停止状态显示总数 264。
旧 IOHID 计数仍为 0，这正是新增 HCI 入口解决的路径差异。
实测摘要保存在 `dist/HCI-live-verification-20261031.3.json`。

已实测点击停止后临时监督进程及 Apple 抓取子进程均退出，只留下普通用户主应用。

## 光标输入与识别方式（20261031.4）

用户明确要求的是在其他应用光标处语音输入，而非仅在适配器内显示转写。
新增“识别方式”设置，独立于原有按键映射保存：

- macOS 本机识别：识别开始时记录前台应用及聚焦输入框，最终结果只提交一次。
  焦点未变时通过正常粘贴输入，并恢复剪贴板。
  不自动按回车、不激活其他窗口；焦点改变或没有可写输入框时仅保留结果并报告原因。
- 外部语音输入法（微信等）：适配器不再调用 Speech，也不再次写入识别结果。
  遥控器按住麦克风时临时把系统默认输入设备切为 BlackHole 2ch，发送配置的外部语音快捷键；
  松开后释放快捷键并恢复先前的默认输入设备。
  若用户在此期间手动更改默认输入，恢复逻辑不覆盖该选择。
  默认快捷键为这台机器此前已经触发微信语音的 Fn；可使用既有键盘选择器独立修改，
  并支持需要再次发送快捷键才能结束的外部输入法。
- 只有用户启用语音输入时，麦克风键才由所选语音模式处理；原有按键映射不被改写。
- 目前此版本已通过 Release 构建、自测及两套独立签名校验；
  光标输入和外部输入法仍需分别记录真实操作验收，不能沿用 20261031.3 的适配器内转写结果冒充。

### 浏览器写入失败与修复（20261031.6）

用户报告无法写入，现场确认适配器显示已输入到 Microsoft Edge，但浏览器 textarea 仍为空。
20261031.4 的 AXSelectedText 写入返回 success 并不代表 Chromium 实际修改了输入值。
去掉该写入路径，改为标准 Cmd+V；300 ms 后通过 AXValue 回读实际输入值并与预期插入结果比较。
只有回读匹配才显示“已确认输入”，未变化或不能回读时分别报告真实状态。
增加“测试光标输入（5秒后）”，用固定文字单独验证写入，不需要再次说话或蓝牙认证。
20261031.6 细分前台仍为适配器、无法取得聚焦控件、非普通文本控件等失败原因。
自动化工具操作浏览器控件时系统前台仍为 ChatGPT，不能把浏览器自己的“聚焦”状态当成系统前台焦点。
20261031.7 的自测按钮由应用通过 NSWorkspace 主动打开并激活随包附带的独立测试页，随后调用
与 Speech 最终结果相同的 CursorTextInput.insert 路径。
实测 Edge textarea 的 AXValue 与截图均显示“光标输入测试成功”，适配器回读状态为
“已确认输入到 Microsoft Edge”。固定文字写入已通过，证据在
`dist/cursor-input-verification-20261031.7.json`。
此版本的遥控器语音到光标完整链路及外部微信模式仍需分别验收，不能以固定文字测试冒充。

### 微信流式模式修正（20261031.8）

初次微信测试没有写入。WeType 实际日志显示它仍从 BuiltInMicrophoneDevice 录音；
设置 UI 确认其麦克风固定为 MacBook Air 麦克风，未跟随系统默认输入。
排查中临时选过 BlackHole，现已按用户要求恢复为“自动检测”，不永久固定虚拟麦克风。

用户指定参考 VibeStick 仓库的 `docs/WECHAT_INPUT.md` 及
`bridge/tools/vibe_stick_wechat_input.swift`。本次采用其会话行为：

- 开始时保存原输入源及系统默认麦克风，选中已启用且可选择的微信输入源，再临时切到 BlackHole。
- 发送正确 Fn flagsChanged 按下事件，100 ms 用于输入源稳定，保留合计 450 ms 启动音频缓冲。
- 遥控器 F7 持续解码并写入 BlackHole；不经本机 Speech 二次转写，也不等待整段录音结束才传递。
- 等实际音频队列排空后保留 800 ms 尾部静音，释放 Fn，恢复原默认麦克风和原输入源。
- 去掉每个 F7 音频包再次唤起外部输入的路径；唤起只由真实麦克风按下事件启动，防止松手后尾包重新按下 Fn。
- BlackHole 队列上限调为 700 ms，以容纳启动缓冲；这不是在原生模式强加 700 ms 播放延迟。

更新前系统默认输入已独立核对为 MacBook Air 麦克风。20261031.8 还需真实微信实时输入及结束恢复验收。
