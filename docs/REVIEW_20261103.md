# 2026-11-03 整体 Review 与验证

范围：本次语音适配全部源码差异、临时权限/进程边界、键盘隔离、协议解码、两种识别方式、微信组件、两种架构打包和当前文档。
该审查不等于 Apple 安全审计，也不声称私有蓝牙协议已全部逆向。

## Review 发现并修复

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| HID 错误报告被当成新按键状态 | 真机曾出现六个 `0x01` 的 rollover，可能错误释放/重复触发麦克风 | 拒绝 rollover/POSTFail/undefined 及无效长度/ID；回归验证按住→错误报告→相同按住不发生松开或第二次按下 |
| IOHIDManager open 返回失败后未 close | manager 内部可能仍保持 open，停止后再次连接可能意外被接管 | 独立记录调用过 open，停止总是关闭；依据 Apple IOKitUser 实现的状态顺序复核 |
| 按住配置修饰键期间启用语音/改变配置 | 松开可能走新的语音分支，未释放原绑定 | 松开优先释放实际保存的 held binding |
| macOS Speech 新句开始取消旧任务 | 旧句最终识别结果可能丢失，旧回调也可能清空新 request | 每句独立任务/输入目标，结果按句序提交；回归覆盖旧句晚完成、结果乱序、重复最终结果和剪贴板提交串行化 |
| 修改外部快捷键仍保留上一会话输出状态 | 切换Fn/通用快捷键后可能不送音 | 改配置先停用并恢复现场；通用外部音频路径明确恢复直接BlackHole输出 |
| 诊断页仍显示“尚未收到设备报告” | HCI 实际工作而旧 IOHID 计数不变，误导用户 | 显示前台真实收到的目标独占状态、K 和 F7 计数 |
| Swift 组件默认最低系统为 26.0 | 与主应用声明的 macOS 14 不一致 | 两个架构的组件明确 target macOS 14，检查 Mach-O LC_BUILD_VERSION |
| Intel 打包漏带微信组件及测试页 | Intel 微信模式无法使用 | Intel 独立入口包含对应架构组件/许可证/测试页，保留独立 SBC 库和产物 |
| ARM 脚本硬编码 SwiftPM 二进制位置 | 当前构建后端输出到 `.build/out`，打包会读错文件或失败 | 使用相同构建参数的 `--show-bin-path` |
| 打包 SDK 固定且本机不存在 | 无法复现实际构建 | 保留默认 15.4，允许明确设置 `IPRC1000_SDK_PATH`；本次使用实际安装的 26.5 |
| 文档仍描述全局键盘钩子/语音未实现 | 与已验证路径不一致 | 新增独立协议/实现/验证文档，更新 README，历史章节标明日期；补 VibeStick MIT 来源说明 |

本轮不安装修改后的源码构建 `.34`，保留本机正在使用、已真机验证的 `.33`。不重新请求管理员认证，不安装后台服务。

## 自动验证

- 使用 MacOSX26.5 SDK、Release 配置及 `/private/tmp/iprc1000-module-cache` 构建；项目默认15.4 SDK在本机未安装。
- `--self-test`：协议边界、目标身份、键盘状态、序号/缺口/重采样、真实管道背压/EPIPE、分帧/重启水位、Speech结果时序。
- `--diagnose-exclusive` 缺少目标地址时立即返回64，不再空等15分钟。
- `Tools/TargetBluetoothProbe --self-test`：ASan/UBSan 通过，仅测试构造数据，不打开设备或通道。
- ARM及Intel（Rosetta）软件自测通过；定向实验工具ASan/UBSan自测通过。
- 实际执行 ARM/Intel 打包入口；Local 使用本机既有证书，GitHub-AdHoc 使用 `codesign --sign -`，各自独立命名并严格验签。
- 核对主程序、组件的 Mach-O 架构与最低系统；Intel 软件自测通过 Rosetta，只代表该主机的软件测试，不等于 Intel 真机蓝牙验收。
- 静音组件检查只输出构造 PCM 至 BlackHole，不触发 Fn、不录音、不切默认麦克风。
- `git diff --check`、脚本语法、签名variant不匹配拒绝、文档相对链接、无全局输入监听、待提交文件检查。

本机签名身份、私钥、原始蓝牙抓包和真实录音不会提交；`dist/`、`.build/` 均被忽略。

## 保留限制

1. 临时提权依赖已弃用的 AuthorizationExecuteWithPrivileges，启动捕获可能再次要求认证；用户选择不安装免重复认证的系统组件。
2. PacketLogger 在管理员进程中读取本机HCI流，然后只处理目标F7；并非底层单设备音频入口，也没有把Apple工具打进发行包。
3. 需有效蓝牙日志环境、Apple PacketLogger、输入监控、辅助功能、BlackHole及相应输入法/本机中文模型。
4. `.34` review后源码修复有自动验证，尚未替换 `.33` 做全新权限/实物回归；macOS Speech乱序处理的状态测试不等于Speech服务实机验收。
5. Intel的架构、打包和软件自测不代表实际Intel Mac上的HID/权限/微信行为已通过。
6. 正常退出会清理；强杀管理员进程不能保证defer执行。尚未实现受监督的系统服务。
7. 其他输入法/快捷键未完成端到端验收；已验证的微信路径使用Fn长按与“自动检测”麦克风。

## 复现

```sh
export IPRC1000_SDK_PATH=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
SDKROOT="$IPRC1000_SDK_PATH" \
CLANG_MODULE_CACHE_PATH=/private/tmp/iprc1000-module-cache \
SWIFT_MODULECACHE_PATH=/private/tmp/iprc1000-module-cache \
  swift build --disable-sandbox -c release --sdk "$IPRC1000_SDK_PATH"
# 用相同SDK和模块缓存环境调用 --show-bin-path 获取实际二进制目录。
# 两个签名产物必须分开，不把Local证书私钥或原始抓包上传。
IPRC1000_PACKAGE_VARIANT=GitHub-AdHoc IPRC1000_CODE_SIGN_IDENTITY=- scripts/package-app.sh
IPRC1000_PACKAGE_VARIANT=Local IPRC1000_CODE_SIGN_IDENTITY="本机签名身份" scripts/package-app.sh
# Intel使用 package-app-intel.sh；保持上述两个variant分别构建。
```
