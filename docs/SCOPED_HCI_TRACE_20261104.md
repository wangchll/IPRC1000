# 不依赖过期描述文件的原生接收候选

目标仍是长期遥控器语音输入。本阶段先用一个五分钟、有正常认证和自动恢复的实验验证系统入口；限时实验通过不等于长期适配已经完成。

## 与此前方案的区别

不运行 PacketLogger.app、不安装蓝牙描述文件、不修改授权数据库、不启用 `HCISkipAuth`。现有目标 IOHID 独占、F7 PCM、微信 Fn/BlackHole 和光标写入沿用同一链路。只有新按钮“验证免描述文件接收（限时5分钟）”会申请临时系统配置；普通启动按键或音频不隐式开启它。

这仍是全机 HCI 诊断入口，适配器只向前台传递通过目标身份与通道校验的 F7。它不是单设备底层数据流，也不是 macOS 承诺稳定的公开录音 API。

## 本机只读代码核验

macOS 26.6.2 / 25G83 的 `/usr/sbin/bluetoothd` 包含 x86_64 和 arm64e。只读反汇编确认了两个独立分支：

- arm64e `0x1000fbe74` 检查 skip-auth 状态；设置后直接进入“PacketLogger skipping authentication”路径。保持 false 则执行现有 audit-token / Authorization 凭据流程。
- arm64e `0x1000fc04c` 检查另一个实时接收状态；未开启时生成类型 0xFC 的 `Bluetooth Profile Required` 诊断记录。配置加载器单独读取 `HCILiveTraces` 与 `HCISkipAuth`，前者进入实时追踪配置，后者经单独 setter 设置跳过认证标志。
- 同一文件 x86_64 slice 中，实时状态在 `0x1000fa6cd` 从配置块的 liveTracing 字段赋值，skip-auth 在 `0x1000fa84c` 单独赋值；认证入口与追踪入口分别检查这两个状态。

这些是当前二进制的静态证据，支持“开启实时诊断同时保留认证”的实验，并非已经收到真实 F7。生产代码不使用上述地址、注入或修改系统指令。

## 配置和恢复

已有的临时管理员进程另启一个同签名程序的有限生命周期清理进程；后者通过 CFPreferences 管理 `com.apple.MobileBluetooth.debug` 的普通整机 `HCITraces` 偏好，没有 HCI、HID、麦克风或授权服务连接。此修正尚未替换已安装的 `.38`。

实验设置：实时追踪和原始音频/HID 追踪开启，`HCISkipAuth=false`，`HCIFileTraces=false`。临时 `AutoDisableTime` 请求系统在六分钟后停用，日期格式依据当前系统加载器；这一附加保险尚未实机验证，主要恢复依靠清理进程。

- 原偏好保存到 root 专属 0700 目录中的 0600 日志文件，日志只含配置快照，没有抓包或音频。
- 独占文件锁拒绝并发修改；既有活跃诊断、错误格式、受管理偏好或其他作用域覆盖均拒绝开启。事务日志拒绝非属主、不安全权限、硬链接或符号链接。
- 发送 SIGUSR1 请求蓝牙服务重新加载配置，不停止或重启该服务；实机设备是否有短暂影响仍待观察。
- 停止、主进程结束或父进程崩溃导致控制管道 EOF，清理进程恢复配置；五分钟到期也恢复。通过 CFPreferences 恢复原偏好值；若其他配置发生变化，只恢复仍等于本程序设置值的字段，保留外部修改，不改动该域其他键。
- 未恢复成功的事务保留快照供下次恢复。两个进程同时遭到强杀、系统崩溃以及系统自动停用行为尚未完成实机验收，不能称为无条件恢复保证。

本阶段不安装 launchd 服务。用户之前拒绝的常驻组件仍未安装。是否将窗口延长为应用运行期间的长期租约，要以入口接收、恢复和稳定性验证为前提，不能通过反复续装描述文件代替。

## 已有离线验证

实际配置事务的 ASan 测试覆盖：保留认证、关闭文件追踪、精确恢复、保留外部变更、并发锁、遗留事务恢复、重载失败回滚、符号链接与不安全权限拒绝。进程测试使用同一等待/恢复实现和临时目录，实际覆盖 EOF、停止命令、三秒超时和对持有管道的父进程发送 SIGKILL 后的恢复。没有修改系统蓝牙配置。

## 实机验收门槛

1. 明确获得本次全机临时诊断配置授权，之后才点击限时按钮。
2. 启动后读回关键设置为 `HCISkipAuth=false` / `HCIFileTraces=false`；系统仍走正常认证；不运行 PacketLogger。
3. 真实遥控器一次按住，同时检查目标 IOHID 按下/松开、目标连接/CID、真实 F7、PCM 电平、微信文字和 M/I 漏键；不能只凭总封装数宣布成功。
4. 停止后核对配置恢复、捕获关闭、键盘仍独占，Fn/麦克风恢复；再检验退出、父进程异常和重新启动。
5. 以上证明后继续实现长期运行、休眠重连、冷首键与连续输入，最后才进行完整交付审查与发布。
