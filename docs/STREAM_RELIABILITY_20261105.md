# `.43` 连续语音与异常清理优化

## 范围

保留`.42`真实冷首词通过的缓存/Fn/20ms送音路径，以及仅目标遥控器独占和已授权的持续诊断范围。本轮只修正音频发送背压及结束清理，不修改其他键盘输入，不安装服务，不重装描述文件。

## 修正

此前`FileHandle.write`位于串行异步队列；子组件停止读管道时，写入会阻塞，后续音频及关闭操作继续排队，缓存上限只覆盖启动和下一句等待阶段，未覆盖实时发送队列。

新增实际管道写入器：待发送PCM最多五秒（160000字节），非阻塞写入，单批两秒未完成即报错；取消标志使阻塞等待最多50ms一次检查，关闭在同一写入队列执行，避免跨线程关闭后文件描述符复用。正常结束按接收顺序排空并关闭；错误、积压超限和取消会释放Fn、恢复麦克风，并结束本程序自己的异常微信组件。

发送结束增加十秒兜底，防止组件在CoreAudio排空或退出时一直不结束。回调仍按进程身份检查，旧组件超时不能取消新一句。停止语音或组件异常不释放独占键盘进程。

前台收到周期诊断状态时同步刷新自身已接受F7计数，减少末尾未满50帧导致界面长期显示旧值的情况；原生队列丢帧与前台帧数仍是不同指标，不据此宣称端到端零丢帧。

## 自动验证

`Tools/PCMStreamWriterSelfTest`使用生产写入器及真实本地管道，在Swift6、warnings-as-errors和ASan下验证：

- 两段PCM逐字节保持顺序并排空；
- 子组件不读取时缓存拒绝超限；
- 写入阻塞时取消不需要等两秒超时；
- 正常finish在不读取时两秒后报告stall；
- 读端退出产生EPIPE而不以SIGPIPE杀死应用；
- 不同线程同时append/finish时，已接受的数据不会排在关闭之后。

Release构建和应用自测通过。当前已安装`.42`及其按键/持续语音仍运行；`.43`尚需签名包内正常微信回放验证，未声称实物、休眠或全天稳定性已验收。
